# Style Selection

## Activation
Use for style selection when it is a concrete work item. Search aliases: stil seçimi,görsel tarz. Do not activate for generic video language alone. Read the project brief and relevant hard locks before changing any asset.

## Inputs and output
- Inputs: User brief, explicit constraints, available resources.
- Output: Approved decision record or production plan.
- Required capability: No specific adapter is mandated; inspect the chosen implementation path.
- Evidence bundle: brief, reference board and feasibility record.

## Production recipe
1. Locate shot/task IDs, approved assets, frame rate, duration and relevant constraints. Verify required capability; record assumptions and do not silently substitute missing resources.
2. Compare stylistic options against brief, asset availability and compute budget.
3. Run one identical 2-second hero test per candidate style; evaluate readability, rendering cost and asset feasibility before committing.
4. Record actual parameters in the editable source or project manifest; produce a representative preview or dry run before full execution. Apply only parameters relevant to the brief, not every technique in this skill.
5. Compare the approved brief, storyboard and hero frames before committing production resources.

## Acceptance criteria
- Selected style has a justified feasible rendering path.
- Record the concrete evidence path and frame/time range or measurement, plus target/tolerance and result (`pass`, `fail`, `review`, `blocked`, `not-applicable`). Never award a pass for an unperformed check.
- Check this stage against active project locks and the production profile. Aesthetic judgment requires actual visual/audio review; technical gate success is necessary but not sufficient for release.

## Failure and repair
Return to the visual thesis; replace the conflicting motif or reduce scope rather than hiding the conflict with effects. If the required implementation is absent, return the exact blocker and an executable plan; do not present guidance as a rendered result. Recheck the original acceptance condition after repair.
