# Corporate Film

## Activation
Use for corporate film when it is a concrete work item. Search aliases: kurumsal video,firma tanıtımı. Do not activate for generic video language alone. Read the project brief and relevant hard locks before changing any asset.

## Inputs and output
- Inputs: Brief, audience, requested platform, media and claim evidence.
- Output: Genre-specific production plan and reference selection.
- Required capability: No specific adapter is mandated; inspect the chosen implementation path.
- Evidence bundle: format-specific brief, shot plan and final deliverable.

## Production recipe
1. Locate shot/task IDs, approved assets, frame rate, duration and relevant constraints. Verify required capability; record assumptions and do not silently substitute missing resources.
2. Connect brand purpose, credible evidence and human or operational visuals.
3. Build audience-specific value narrative with documented evidence, consistent brand tokens and readable titles; avoid generic stock montage.
4. Record actual parameters in the editable source or project manifest; produce a representative preview or dry run before full execution. Apply only parameters relevant to the brief, not every technique in this skill.
5. Review audience, truthful content, pacing, format constraints and target-device playback.

## Acceptance criteria
- Brand tone and claims remain consistent throughout.
- Record the concrete evidence path and frame/time range or measurement, plus target/tolerance and result (`pass`, `fail`, `review`, `blocked`, `not-applicable`). Never award a pass for an unperformed check.
- Check this stage against active project locks and the production profile. Aesthetic judgment requires actual visual/audio review; technical gate success is necessary but not sufficient for release.

## Failure and repair
Revise narrative or crop instead of padding with generic stock; preserve facts and approvals. If the required implementation is absent, return the exact blocker and an executable plan; do not present guidance as a rendered result. Recheck the original acceptance condition after repair.
