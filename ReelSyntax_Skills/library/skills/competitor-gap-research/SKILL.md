# Competitor Gap Research

## Activation
Use for competitor gap research when it is a concrete work item. Search aliases: rakip araştırması,yeni özellik araştır. Do not activate for generic video language alone. Read the project brief and relevant hard locks before changing any asset.

## Inputs and output
- Inputs: Agent request, registry, repository state and applicable permissions.
- Output: Skill package, routing result, test or integration artifact.
- Required capability: No specific adapter is mandated; inspect the chosen implementation path.
- Evidence bundle: skill metadata, source/license log, route/evaluation results.

## Production recipe
1. Locate shot/task IDs, approved assets, frame rate, duration and relevant constraints. Verify required capability; record assumptions and do not silently substitute missing resources.
2. Compare current primary docs, issues and releases against actual ReelSyntax capabilities; prioritize compatible improvements.
3. Research current primary repo/docs and licenses; record feature gaps, evidence and priority, independently implement useful additions and test them.
4. Record actual parameters in the editable source or project manifest; produce a representative preview or dry run before full execution. Apply only parameters relevant to the brief, not every technique in this skill.
5. Test positive, negative and mixed intents plus actual implementation claims; verify budget and security.

## Acceptance criteria
- Gap record contains evidence, license cautions, acceptance criteria and implementation status.
- Record the concrete evidence path and frame/time range or measurement, plus target/tolerance and result (`pass`, `fail`, `review`, `blocked`, `not-applicable`). Never award a pass for an unperformed check.
- Check this stage against active project locks and the production profile. Aesthetic judgment requires actual visual/audio review; technical gate success is necessary but not sufficient for release.

## Failure and repair
Refine scope/aliases/instructions or split skill; reindex and run regression suite before release. If the required implementation is absent, return the exact blocker and an executable plan; do not present guidance as a rendered result. Recheck the original acceptance condition after repair.
