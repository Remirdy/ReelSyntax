# Repository To Video

## Activation
Use for repository to video when it is a concrete work item. Search aliases: repodan video,github tanıtım. Do not activate for generic video language alone. Read the project brief and relevant hard locks before changing any asset.

## Inputs and output
- Inputs: Authorized source, viewport, demo steps and privacy constraints.
- Output: Capture manifest, frames or truthful demo storyboard.
- Required capability: No specific adapter is mandated; inspect the chosen implementation path.
- Evidence bundle: authorized source and capture manifest, frame references and action log.

## Production recipe
1. Locate shot/task IDs, approved assets, frame rate, duration and relevant constraints. Verify required capability; record assumptions and do not silently substitute missing resources.
2. Inspect README, implemented features and runnable demo before planning product film.
3. Inspect repo entrypoints, README and runnable demo; use real documented features/screens, isolated launch and licensed assets; never fabricate functionality.
4. Record actual parameters in the editable source or project manifest; produce a representative preview or dry run before full execution. Apply only parameters relevant to the brief, not every technique in this skill.
5. Verify actual source state, viewport, fonts, privacy and content against captured frames.

## Acceptance criteria
- Every demonstrated feature exists or is labeled conceptual.
- Record the concrete evidence path and frame/time range or measurement, plus target/tolerance and result (`pass`, `fail`, `review`, `blocked`, `not-applicable`). Never award a pass for an unperformed check.
- Check this stage against active project locks and the production profile. Aesthetic judgment requires actual visual/audio review; technical gate success is necessary but not sufficient for release.

## Failure and repair
Recapture from reproducible state or clearly label mock; never fabricate functionality or leak source data. If the required implementation is absent, return the exact blocker and an executable plan; do not present guidance as a rendered result. Recheck the original acceptance condition after repair.
